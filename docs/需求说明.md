| 项目 | 内容 |

## 1. 项目背景与目标

### 1.1 背景

日常网络运营数据存放在公共数据库中，运营人员和管理人员需要人工查询、手工整理，再复制粘贴发到钉钉群。效率低、容易出错、时效性差。

### 1.2 目标

建设一个轻量级 Web 系统，让**不懂技术的运营人员**通过极少的配置（最好只是上传一份样例报表），就能把数据库中的运营数据自动、定时地推送到指定钉钉群，并按数据内容自动 @ 到对应负责人。

### 1.3 设计原则

- **极简优先**：新建一条推送规则不超过 3 步、3 分钟。
- **约定优于配置**：能从数据里推断出来的，绝不让人手填。
- **只读安全**：数据库连接全程只读，系统不修改任何业务数据。
- **可追溯**：每条规则、每次发送都有记录，失败可查、可重发。

### 1.4 已确认的关键决策

| 决策项 | 结论 | 影响 |
|---|---|---|
| 用户身份与归属地 | 系统内建「人员信息表」，每人标注归属地；用户进入系统时以手机号识别身份 | FR-7 |
| 归属地权限 | 按人员信息表上的归属地过滤数据，数据层强制注入 | FR-7 |
| 钉钉接入 | 自定义群机器人 Webhook | FR-4 |
| @ 人员方式 | 按手机号 @ | FR-5 |
| 数据库 | PostgreSQL（只读账号） | FR-1 |
| 调度粒度 | 小时级（预留分钟级扩展） | FR-6 |

## 2. 用户角色

| 角色 | 使用频率 | 核心诉求 |
|---|---|---|
| 运营人员 | 高 | 3 分钟配好一条日报，之后每天自动推 |
| 管理人员 | 中 | 看汇总、看异常，被 @ 时能直接定位问题 |
| 系统管理员 | 低 | 维护数据源、钉钉配置、人员信息表 |

系统不设密码登录。用户进入系统时输入手机号识别身份，系统据人员信息表判定归属地。

---

## 3. 核心流程

```
管理员：配置 PostgreSQL 只读数据源 + 导入人员信息表（一次性）
   ↓
用户：进入系统 → 输入手机号 → 系统识别归属地 → 只可见本归属地数据
   ↓
运营人员：新建推送规则
   ├─ 方式 A：上传样例报表 → 系统自动生成规则 → 微调确认   ← 主推
   └─ 方式 B：下拉选表、勾选字段 → 可视化配置
   ↓
选择钉钉群 + 配置 @ 人员规则 + 设置发送频率
   ↓
保存 → 调度器按频率自动执行 → 发送到钉钉群 → 记录执行结果
```

## 4. 功能需求

### FR-1 数据源管理（管理员）

- 配置 PostgreSQL 只读连接：主机、端口、库名、账号、密码（加密存储）。
- 支持「测试连接」。
- 连接成功后自动读取并缓存表 / 视图清单及字段元数据（表名、字段名、类型、字段注释）。
- 支持手动 / 定时刷新元数据缓存。
- 预留多数据源能力，一期只做 1 个。

### FR-2 推送规则配置（核心，运营人员）

入口：新建推送。

**主流程：从数据表出发，自助取数生成报表**

1. 选数据源 → 浏览表清单（支持搜索）。
2. 选表 → 展示字段列表（字段名、类型、注释、样例值）。
3. 勾选需要的字段，配置筛选条件、分组汇总、排序、取数上限。
4. **实时预览**：点「预览」立刻看到取到的数据表格。
5. 生成消息：一键把预览数据渲染成 Markdown 表格，或自定义模板。
6. 配置发送目标、@ 人员、频率，保存。

全程不需要写 SQL。高级用户可展开「自定义 SQL」（仅允许 SELECT，且系统强制注入归属地过滤条件）。

**辅助能力：上传样例报表**

上传一份 Excel / CSV 样例，系统只把它当作**样式参考**，用来：

1. 生成消息模板初稿（用户期望的排版长什么样）。
2. 在字段列表里高亮**推荐的字段**（样例表头与数据库字段做智能匹配）。
3. 校验样例里出现的归属地名称是否与归属地字典一致，未知名称提醒人工确认。

注意：样例文件本身**不产生数据**，取数一律以数据源中的真实表为准。

**规则配置项**

| 配置项 | 说明 |
|---|---|
| 时间范围 | 今天 / 昨天 / 近 N 天 / 近 N 小时 / 本周 / 本月 / 自定义 |
| 筛选条件 | 字段 等于 / 大于 / 小于 / 包含 / 区间，多条件支持与、或 |
| 分组汇总 | 分组维度 + 聚合方式（求和 / 平均 / 计数 / 最大 / 最小） |
| 取数上限 | 限制单条消息行数，防止刷屏 |
| 空数据处理 | 无数据时是否发送、发送什么内容 |

### FR-3 消息模板

- 支持钉钉消息类型：Markdown、文本、ActionCard。
- 模板中可插入字段占位符，例如 单位、当日退服次数。
- 支持表格循环渲染：一组数据自动渲染成 Markdown 表格。
- 支持异常高亮：指标超过阈值时自动标红 / 加粗。
- 提供「用样例数据预览」，所见即所得。
- 系统根据样例报表自动生成模板初稿，用户只需微调。

### FR-4 钉钉发送配置（管理员）

- 配置钉钉群机器人：名称、Webhook 地址、加签密钥 Secret。
- 消息体使用 Markdown 或文本类型，`atMobiles` 字段承载 @ 手机号。
- 支持「发送测试消息」验证配置。
- 一个群保存为一个「发送目标」，规则里下拉选择。
- 支持一个规则同时发多个群。

### FR-5 @ 人员机制

| 类型 | 说明 |
|---|---|
| 固定 @ | 每次推送固定 @ 若干人（从人员信息表选择） |
| 动态 @ | 数据中某字段（如归属地 / 负责人）→ 查人员信息表得手机号 → @ 对应人 |
| 条件 @ | 例如「当日退服次数 > 阈值」时 @ 该区县负责人，正常时不 @ |
| @ 所有人 | 可选，紧急通报场景用 |

- 所有 @ 最终都转成手机号，通过 Webhook 的 `atMobiles` 下发。
- **前置依赖**：手机号必须在机器人所在企业内可匹配，否则 @ 不生效（钉钉会照常发消息但不会真正 @ 到人）。上线前需先验证。

### FR-6 调度与触发

| 频率 | 说明 |
|---|---|
| 小时级 | 每小时执行（准实时），轮询间隔可配 |
| 每天 | 指定时间点（如 08:30），支持「工作日」或「自然日」 |
| 每周 | 指定星期几 + 时间点 |
| 手动 | 「立即发送一次」按钮 |

- 架构上预留分钟级扩展，一期不实现。
- 失败重试：自动重试 N 次，间隔可配。
- 并发控制：同一条规则不会重复执行。
- 支持按归属地错峰发送，避免集中推送。

### FR-7 身份识别与归属地权限

**模型**

1. 系统维护一张「人员信息表」，每人一条记录：姓名、手机号、归属地、岗位 / 角色。支持 Excel 导入。
2. 用户进入系统时输入手机号，系统查表确认身份并确定归属地。
3. 所有数据查询强制注入归属地过滤（数据层兜底，不能只靠前端隐藏）。
4. 用户只能看到、只能配置自己归属地的规则和数据。
5. 管理员身份（信息表里标角色）可见全部归属地。

**必须配套：归属地字典与别名表**

真实报表里同一个区的叫法不统一（详见 5.3），必须建标准名 + 别名映射，取数、过滤、权限、@人 全部走标准名。否则权限会失效。

**待确认**

- 手机号识别是否需要一道校验（如短信验证码 / 口令）？目前方案是「输手机号即进」，属于防误操作级别，不防越权。
- 是否需要一个「游客 / 全区」身份用于浏览汇总数据。

### FR-8 执行记录与日志

- 每次发送记录：时间、规则名、发送群、消息内容快照、成功 / 失败、错误原因。
- 支持按规则、时间、状态筛选查询。
- 发送失败支持一键重发。
- 记录保留周期可配置。

### FR-9 规则管理

- 规则列表：名称、发送群、频率、状态（启用 / 停用）、最近发送时间、最近发送状态。
- 操作：编辑、复制、启用 / 停用、立即执行、删除、查看记录。
- 按归属地隔离：用户只能看到自己归属地的规则。

## 5. 样例报表解析实录

分析对象：`移动网故障日通报(9月8日).xlsx`（真实报表）

### 5.1 文件概况

| Sheet | 定位 | 规模 | 说明 |
|---|---|---|---|
| 妨业故障通报 | 汇总统计 | 24 行 × 9 列 | 按区县汇总的指标表，**应是发钉钉的主体内容** |
| 当日妨业故障 | 当日明细 | 345 行 × 5 列 | 区县 / 基站名称 / 小区名称 / 发生时间 / 清除时间 |
| 9月妨业故障 | 月度明细 | 2286 行 × 45 列 | 全量故障明细宽表 |

Sheet「妨业故障通报」字段：单位、小区总数、平均退服时长、序时进度、平均退服次数、序时进度、当日退服次数、当日超频小区数。

Sheet「9月妨业故障」关键字段（共 45 列，节选）：告警流水号、城市、区县、区县-映射人力、网格名称、厂家名称、网络类型、设备类型、基站名称、基站等级、小区名称、发生时间、清除时间、类型权重、核减前/后折算退服次数、核减前/后折算退服时长、产权归属、故障原因描述、入网工单、故障分类、基站状态、是否为室分、ECI、GCI、机房名称、场景等。

### 5.2 解析器必须处理的 6 类脏数据

这 6 点直接决定「上传样例自动生成规则」的成败。

| # | 现象 | 真实例子 | 处理策略 |
|---|---|---|---|
| 1 | 表头不在第一行 | Sheet1 第 1 行是大标题（A1:H1 合并单元格），第 2 行才是表头 | 自动探测表头行：取「非空单元格最多、且下一行起连续多行为数据」的行 |
| 2 | 重复列名 | Sheet1 的「序时进度」出现两次 | 自动去重加后缀：序时进度、序时进度_2 |
| 3 | 汇总行混在明细中 | 「全区」「当日指标」「月指标」与 18 个区县并列 | 内置汇总关键词库，标记为汇总行，默认排除出明细、单独处理 |
| 4 | **区县名称不统一** | 见 5.3，最严重 | 归属地字典 + 别名归一化 |
| 5 | 时间是完整日期时间 | 2026-09-08 23:43:39 | 自动识别为 datetime，支持按天 / 按小时筛选 |
| 6 | 空列与空值 | Sheet3「故障分类」整列 2285 行全空；「故障原因描述」大量为空 | 统计空值率，高空值率的列在选择器里降权或折叠 |

### 5.3 归属地名称不统一（必须解决的关键问题）

同一份文件里，同一个区的不同叫法：

| 报表中的写法 | 标准名 | 问题类型 |
|---|---|---|
| 襄都 / 桥东区 | 襄都区 | 行政区改名（桥东区 → 襄都区） |
| 信都 / 桥西区 | 信都区 | 行政区改名（桥西区 → 信都区） |
| 内邱 / 内丘 | 内丘县 | 异体字混用（同一 Sheet 内同时出现） |
| 南宫 / 南宫市 | 南宫市 | 简称 vs 全称 |
| 宁晋 / 宁晋县 | 宁晋县 | 简称 vs 全称 |
| 沙河 / 沙河市 | 沙河市 | 简称 vs 全称 |
| 达活 | 无 | 脏数据，不是区县名 |

各 Sheet 的区县集合还不一样：Sheet1 用简称（18 个），Sheet2 混用（含「内邱」「内丘」「达活」），Sheet3 用全称（19 个）。

**结论**：系统必须内置「归属地标准名 + 别名表」，并在样例导入环节做归一化校验，发现未知名称时提示人工确认。不解决这一条，归属地权限和 @ 人都会失效。

### 5.4 三张表推测的推送形态（待确认）

| 场景 | 取数 | 消息形态 | @ 对象 |
|---|---|---|---|
| 每日通报 | 汇总表，取昨日 / 最近小时 | Markdown 表格，按区县列指标 | 无，或全区负责人 |
| 超频预警 | 汇总表，当日超频小区数 > 0 | 高亮异常行 | 该区县负责人 |
| 故障明细 | 当日明细，按归属地过滤 | 明细列表（限前 N 条） | 该区县负责人 |

## 10. 数据文件导入（v0.3 新增）

### 10.1 目标

按固定周期、时间点扫描指定目录，获取以 `{前缀}_{YYYYMMDD}.txt` 命名的数据文件（如 `dws_iscs_wireless_alarm_wide_all_20260831`、`hb_wireless_alarm_noservice_20260831`），自动导入本地数据库，并把新建的本地库作为钉钉推送规则可用的数据源。

### 10.2 已确认的决策

| 决策项 | 结论 |
|---|---|
| 文件日期口径 | 文件名末尾 8 位 YYYYMMDD，每天一份，内容是当月累计 |
| 本地库形态 | 每个文件名前缀一个 SQLite 库，库内一张同名表 |
| 导入策略 | 整表覆盖（当日快照）；同日重复扫描跳过，支持手动强制重导 |
| 时间列 | 不额外加列，直接使用 txt 自带字段（如 `发生时间`、`账期`） |
| 定时方式 | 每天固定时间点扫描，时间可配，默认 08:00 |
| 数据源登记 | 导入成功后自动注册为数据源，`is_public=1` 全员可见 |
| 目录组织 | 单扫描目录（可配置），按文件名前缀自动识别文件类型 |

### 10.3 文件格式约定

- UTF-8（无 BOM）、`|` 分隔、首行表头；任一行字段数与表头不一致则整次导入失败
- 数值列自动推断为 INTEGER / REAL，其余保存为 TEXT；时间字段保留 ISO 文本可直接排序过滤
- 无数据行、空表头等异常均记入导入日志（success / skipped / failed）

### 10.4 验收标准

1. 定时任务按配置时间扫描目录并自动导入新版本文件
2. 首次导入自动建库建表，行数与文件一致
3. 同日重复扫描结果为 skipped，强制重导可覆盖
4. 数据源列表出现自动注册的本地库，非管理员可见且能配规则
5. 管理页可改目录 / 时间、手动导入、查看导入记录
