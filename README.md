# 钉钉运营数据推送系统

用极少的配置，把公共数据库里的运营数据定时推到钉钉群，并按数据内容自动 @ 到对应负责人。

- 面向用户：运营人员、管理人员（不写 SQL、不写代码）
- 数据库：PostgreSQL 只读连接（也支持 MySQL / SQLite）
- 推送：钉钉自定义群机器人 Webhook，按手机号 @ 人
- 权限：内建人员信息表，按归属地隔离数据

---

## 一、快速启动

### 方式 1：一键启动（推荐）

双击项目根目录的 **`启动系统.bat`**，会自动：

1. 首次运行时安装前后端依赖
2. 打开「后端」和「前端」两个命令行窗口
3. 8 秒后自动用浏览器打开 http://localhost:5173/

停止服务：双击 **`停止系统.bat`**。

### 方式 2：手动启动

开两个 PowerShell 窗口：

```powershell
# 窗口 1 —— 后端 API
cd G:\codex\jijiantongzhi\backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 18080
```

```powershell
# 窗口 2 —— 前端页面
cd G:\codex\jijiantongzhi\frontend
npm run dev
```

浏览器访问 http://localhost:5173/

> **端口说明**：后端默认用 **18080**。Windows 上 Hyper-V / WSL 会在 **1024–15000** 里成段保留端口给系统
> （开机后保留段还会变），8080、8000、8010 这类常用端口随时可能绑不上，报 `WinError 10013`。
> 18080 在动态端口段之外，因此默认用它。想看本机保留了哪些段：
> `netsh interface ipv4 show excludedportrange protocol=tcp`；想换端口就改 `backend/run.bat`，
> 并把 `frontend/vite.config.js` 的 `VITE_API_TARGET`（或环境变量）指到同一个端口。

### 往演示库里加自己的报表

演示业务库（`backend/data/demo_business.db`）自带 3 张随机生成的样例表，够跑通流程，但不太像真报表。
这 3 张合成表在每次启动时会检查一次：比当前时间旧 6 小时以上就按当前时间重新生成，
所以「最近 24 小时」这类时间范围永远能查到数，样例规则也不会因为库放久了变成空表。**你自己导进去的表不受影响。**
想拿真实报表试规则，用自带的导入脚本导进去就行 —— **一个工作表导成一张表**：

```powershell
cd backend
python -X utf8 tools/import_report_xlsx.py "G:\codex\邢台移动网故障日通报(9月8日).xlsx" --prefix "9月8日_"
```

以「邢台移动网故障日通报(9月8日)」为例，导完会多出三张表：

| 工作表 | 生成的表 | 内容 |
|---|---|---|
| 妨业故障通报 | `9月8日_妨业故障通报` | 8 列 / 21 行，各区县指标，末尾带「全区」「当日指标」「月指标」汇总行 |
| 当日妨业故障 | `9月8日_当日妨业故障` | 5 列 / 344 行，当日告警明细 |
| 9月妨业故障 | `9月8日_9月妨业故障` | 45 列 / 2285 行，当月全量告警明细 |

脚本的几个约定：

- 表头取前 5 行里非空单元格最多的那一行，「第一行是合并大标题」的报表也能认出来
- 空字段名的列（报表右侧常见的空白列）直接丢掉
- 同名字段自动加 `_2`、`_3` 后缀；想改成好认的名字用 `--rename "序时进度=序时进度_时长,序时进度_2=序时进度_次数"`
- 表名 = `--prefix` + 工作表名；同名表会被覆盖，所以同一份报表重复导入是安全的
- 加 `--dry-run` 可以先看会生成什么，不写库

导完回到「数据源 → 浏览数据」，点左上角「刷新」重建字段缓存，新表就能在规则里选了。

## 二、使用流程

按下面顺序走一遍，大约 10 分钟即可完成首次配置：

1. **数据源** —— 填入 PostgreSQL 只读账号，点「测试」确认连通，系统自动读取表结构
2. **归属地字典** —— 把同一区县的各种写法配成别名（`襄都 / 桥东区`、`内邱 / 内丘`），权限过滤和 @ 人才不会漏
3. **钉钉群** —— 粘贴群机器人的 Webhook 地址（有加签的填上密钥），点「测试发送」确认能收到
4. **人员信息** —— 姓名 + 手机号 + 归属地，支持从 Excel 批量导入
5. **推送规则** —— 选场景模板 → 选表 → 选字段 → 配条件 → 右侧实时预览 → 生成模板 → 保存
6. **系统设置** —— 想用图片推送的话，把「图片服务地址」填成本系统的访问地址（见「以图片形式发送」）

首次启动会带两条演示规则（都已停用，可随时编辑或删除）：

| 规则 | 类型 | 说明 |
|---|---|---|
| 移动网故障日通报（示例） | 统计报表 | 每天 08:30 推送各区县故障指标 |
| 小区重复告警提醒（示例） | 重复次数触发 | 每小时检查最近 24 小时，同一个小区告警 ≥ 3 次才提醒 |

### 推送规则怎么配

**第一步：选场景模板**（新建规则时出现）。选一个最接近的，系统自动把触发条件、频率、模板初稿填好：

| 模板 | 落地方式 |
|---|---|
| 📊 统计报表 | 无条件，有数据就发。日报 / 周报 / 月报 |
| 🔔 重复次数触发 | 同一字段的同一个值累计 ≥ N 次才发，例如同一小区退服 ≥ 3 次 |
| ⏱ 时长触发 | 按对象分组算持续时长，超过 N 分钟才发 |
| 📈 数量触发 | 按区域分组计数，数量 ≥ N 才发 |

规则编辑器右侧是实时预览，分四块：**数据预览**、**图片效果**（开了图片推送才有）、**钉钉消息效果**、**生成的 SQL**。

- **显示字段**：勾选的字段和顺序，就是消息里表格的列和顺序
- **分组汇总**：选「分组字段」（如 `区县`）+「汇总项」，得到各区县故障条数；不填汇总项就是逐条明细。
  汇总方式支持 `计数 / 求和 / 平均 / 最大 / 最小`，还有三种**时长**统计：`最长时长 / 平均时长 / 最短时长`。
  选时长后指定「开始时间」和「结束时间」两个字段即可，**结束时间为空表示还没恢复，按当前时间计算**，所以"一直没好的故障"会被持续盯住
- **筛选条件**：等于 / 包含 / 属于 / 区间 / 为空等 13 种条件。
  下拉里分两组：**表字段**在取数时过滤（SQL 的 `WHERE`），**分组汇总字段**（如「告警次数」）
  是分组算完之后才有的，选它会自动变成分组后过滤（SQL 的 `HAVING`）
- **时间范围**：今天 / 昨天 / 最近 N 天 / 最近 N 小时 / 本周 / 本月。**「最近 N 小时」就是小时级准实时推送**，边界在 Python 侧算好再传给数据库，不受数据库方言影响
- **触发条件**：见下一节
- **异常高亮**：某个数值字段超过阈值时，该单元格在钉钉里标红
- **@ 人**：三种方式 —— 固定人员、按归属地字段匹配负责人、按姓名字段匹配
- **图片发送**：见下一节

### 触发条件：什么时候才真正发出去

这是报表和告警的分界线。三种模式：

| 模式 | 判定方式 |
|---|---|
| 有数据就发送（报表） | 查到什么发什么，日报周报用这个 |
| 满足条件才发送（告警） | 逐行判断字段阈值，只把**命中的行**发出去，没命中的行在预览里是灰的 |
| 同一字段累计达到标准 | 先按一个字段归堆，算一个指标，达到标准的组才发出去 |

「满足条件」模式的判定作用在「分组汇总之后的结果行」上，所以一套配置能覆盖多种触发类型：

| 你要的触发类型 | 怎么配 |
|---|---|
| 按对象卡次数 | 分组字段 = 小区 → 汇总项 `计数 / 告警流水号` → 触发条件 `告警次数 ≥ 3` |
| 按对象卡时长 | 分组字段 = 小区 → 汇总项 `最长时长`（发生时间 → 清除时间）→ 触发条件 `最长时长 ≥ 240` |
| 按区域卡数量 | 分组字段 = 区县 → 汇总项 `计数` → 触发条件 `数量 ≥ 10` |
| 组合条件 | 多个触发条件，选「满足任一」或「同时满足」 |

#### 同一字段累计达到标准

「同一个小区退了 3 次」「某个区县故障合计时长 ≥ 600 分钟」这类诉求，用它最省事：
不用先做「分组汇总」，选三样东西就行 —— **统计字段 + 算法 + 标准值**。

| 选项 | 说明 |
|---|---|
| 统计字段 | 按哪个字段归堆，通常是 `小区名称` / `基站名称` / `区县` |
| 算法 | `出现次数` / `去重数` / `合计` / `平均` / `最大值` / `最小值` |
| 数值字段 | 算法不是「出现次数」时才要选，指对哪个数值字段做统计 |
| 发送标准 | 比较符 + 标准值，例如 `≥ 3` |
| 发送内容 | **每个值汇总一行**：只发达到标准的对象和它的指标；**命中值的原始明细**：把这些对象的每条原始记录都发出来，并在每行后面附上指标 |
| 附带字段 | 汇总模式的可选项，例如带上 `区县`，这样 @人 和分派工单还能用得上 |

几个例子：

- 同一个小区 24 小时内退服 ≥ 3 次 → 统计字段 `小区名称`、算法 `出现次数`、标准 `≥ 3`
- 某个区县故障合计时长 ≥ 600 分钟 → 统计字段 `区县`、算法 `合计`、数值字段 `处理时长_分钟`、标准 `≥ 600`
- 某个基站 3 天内出过 ≥ 2 种不同故障原因 → 统计字段 `基站名称`、算法 `去重数`、数值字段 `故障原因`、标准 `≥ 2`

标准没达到时这条规则这一次就不发消息，所以在「推送记录」里看不到发送记录是正常的。

还有两个配套设置：

- **冷却时间**：同一规则在冷却期内不重复推送，防止同一条告警每小时刷屏。只有真正发出去的执行才会刷新冷却计时
- **最多发送条数**：限制的是**发出去**的行数。触发判定（阈值条件 / 同一字段累计达到标准）
  是在取到的全量数据上算的，不受它影响 —— 判定类规则按 `TRIGGER_SCAN_ROWS`（默认 2 万行）
  取数，取到上限时预览里会提示「判定结果可能不全」，这时缩小时间范围即可

### 归属地取值自动归一

同一个区县在数据库里常有多种写法（`襄都 / 襄都区 / 桥东 / 桥东区`）。不处理的话按区县统计会被拆成 4 行，权限过滤也会漏。

系统在「归属地字段」勾选后自动把取值归一到标准名（`CASE` 表达式，SQLite / PostgreSQL / MySQL 通用），明细和分组统计都生效。想保留原始写法，把「报表里统一显示标准名」取消勾选即可。

选数据表时如果归属地字段还是空的，系统会按列名自动认一个（`区县 / 归属地 / 地市 / 城市 / 单位 / 区域` 等），避免漏配导致越权。

### 消息模板语法

| 写法 | 含义 |
|---|---|
| `{{字段名}}` | 取第一行的这个字段值 |
| `{{表格}}` | 全部数据渲染成对齐文本块（推荐） |
| `{{列表}}` | 每行一条数据，字段加粗 |
| `{{行数}}` | 数据行数（`{{count}}`、`{{总数}}` 也行） |
| `{{日期}}` `{{时间}}` | 渲染时刻 |
| `{{#each}} ... {{/each}}` | 自定义循环，内部可用 `{{字段名}}` 和 `{{序号}}` |

> 钉钉自定义机器人的 markdown **不支持 GFM 表格语法**，所以 `{{表格}}` 输出的是按显示宽度对齐的纯文本块，在钉钉里看起来仍然是整齐的表格。中文按 2 个字符宽度计算。

### 以图片形式发送报表

钉钉自定义机器人**发不了真正的图片文件**，markdown 里也**不支持表格**（`{{表格}}` 只能退化成对齐的文本块）。
打开「图片发送」开关后，系统会把查询结果**画成一张 PNG**，再以 markdown 图片链接的形式发到群里：

- 表格排版完整保留，手机上不用左右滑动、不会串行
- 图片里的表头、斑马纹、数字右对齐、**超标单元格标红**都和网页预览一致
- 可以选「图片之外是否再发一段文字」。勾选时文字部分**自动去掉数据表**，只保留标题和说明（图片里已经有表格了，没必要发两遍）；不勾选就是「标题 + 一张图」
- 图片最多显示多少行可调（默认 30 行），超出部分只在文字里体现

**前置条件：先决定图片存到哪**（「系统设置 → 图片推送」）。钉钉客户端会自己去拉这张图，两种存法二选一：

| 存法 | 适合 | 要填什么 |
|---|---|---|
| 本系统服务器 | 系统本身钉钉能访问到（局域网 / 有域名） | 图片服务地址 = `http://<服务器IP>:18080` 或 `https://你的域名`，系统会列出本机候选地址，点一下即可 |
| 第三方图床 | 系统在内网、手机端拉不到 | 接口地址 + 存储 ID + 令牌，点「测试上传」能传上去就说明配好了 |

图床模式把图片传到公网，返回的 `public_url` 直接进 markdown，**本系统就不必对外可达**了。
系统对接的是同一套 `/api/v2/upload` 接口（`file` + `storage_id` 必填），蜜蜂图床、闪电图床（Boltp）都兼容，
换图床只要改「接口地址 + 存储 ID + 令牌」：

| 图床 | 接口地址 | 存储 ID | 令牌 |
|---|---|---|---|
| 闪电图床（注册即用，推荐） | `https://www.boltp.com/api/v2/upload` | 免费用户 `2`，VIP `3` | **必填**，在后台「我的令牌」里创建（要有上传权限） |
| 蜜蜂图床 | `https://www.beeimg.cn/api/v2/upload` | 公共实例匿名上传只能填 `4`（`1/2/3` 是登录用户的自定义存储） | 选填 |

已实测：蜜蜂图床公共实例 `storage_id=4` 可匿名上传，返回形如 `https://beeimg.us.ci/temp/<md5>.png` 的公网地址，
钉钉客户端能正常拉到；闪电图床的存储**必须登录态**，匿名传 `2` 会报「不存在的储存驱动」，所以令牌必填。
闪电图床还要求**布尔参数按 `0/1` 传**（`is_public` / `is_remove_exif` 传 `true/false` 会被判 422「必须为布尔值」），
系统已按 `0/1` 提交；422 时会直接把图床的字段级报错展示出来，例如 `is_public：是否公开 必须为布尔值`。

⚠️ **匿名上传的额度很小**：实测公共实例「1 小时内只能上传 3 张图片」，限流是**按 IP** 算的。
系统做了三层兜底，不会因为限流丢数据：

1. **同样内容直接复用** —— 图片字节没变（比如数据没更新）时不再重复上传，直接用上次的链接，缓存写在 `backend/data/image_cache.json`
2. **限流自动重试一次**（等 6 秒），仍然失败才放弃
3. **退回完整文字消息**（带表格），并把图床返回的错误写进发送记录

要稳定发图（例如每小时推一条），建议**注册闪电图床 → 在「我的令牌」里创建令牌 → 填到「接口令牌」**里，
用账号自己的存储（免费用户 ID 2）上传，额度比匿名高得多。填了令牌后，「公开可访问 / 相册 / 标签」这些
登录态参数才会生效（匿名时系统不会传，免得被判成参数错误）。

- 填 `127.0.0.1` / `localhost` 时手机端会加载不出图片 —— 系统会在推送提示里警告，但**不会阻断发送**
- 没配好时，图片规则会**自动退回完整文字消息**（带表格），不会出现"既没有图也没有数据"
- 图床模式没成功时会退回文字版，同时把图床返回的错误写进发送记录的提示里
- 本机模式的图片存在 `backend/data/images/`，文件名随机，按「图片保留天数」自动清理（默认 7 天；预览图只留 1 天）；图床模式的图片不落地
- 图床模式会把「图片过期天数」算成 `expired_at` 一起传上去，到期由图床自动删图（填 0 = 永不过期，默认跟随「图片保留天数」）
- 编辑页右侧和发送记录详情里都能直接看到当时那一张图，**预览不会真的上传图床**（避免触发图床限流），只有真正发送时才传

> ⚠️ 图片链接本身不带登录校验，拿到链接的人就能看到图片。因为链接是随机文件名、且图片内容是**按规则里配置的归属地**取出来的，所以按归属地建规则就等于按归属地出图。

### 发送 Excel 数据文件

规则里打开「发送 Excel」后，系统把本次查询结果导出成 `.xlsx`，在消息末尾附一行下载链接
（`📎 数据文件：[点击下载](...)`）。适合「群里看结论、要源数据再下载」的场景。

文件存到哪，跟图片共用「系统设置 → 图片推送」这一处配置：

- **图床模式**：先把 xlsx 传到图床拿公网地址，钉钉手机端直接能下载；图床不收 xlsx（多半返回 422）时，
  自动退回本系统地址，并把图床返回的错误写进发送记录 —— 不会静默丢附件
- **本系统服务器模式**：存到 `backend/data/images/`，文件名带随机串，
  链接形如 `<图片服务地址>/static/reports/r<规则ID>_<时间>_<随机串>.xlsx`
- **没配「图片服务地址」**、图床也没传上去时：**本次只发文字，不生成附件**，并在发送记录里提示去「系统设置」补地址

Excel 文件和报表图片共用「图片保留天数」，到期一起清理。

> ⚠️ 下载链接和图片一样不带登录校验，拿到链接的人就能下载，别给不该外传的数据打开这个开关。

### 发送频率

- **仅手动** —— 只在你点「立即发送」时推
- **每小时** —— 可设 1–24 小时间隔，配合「最近 N 小时」的时间范围就是准实时
- **每天 / 每周** —— 指定时间和星期

## 四、配置项

后端所有配置都可用环境变量覆盖（写在 `backend/.env` 或系统环境变量里）：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SYSTEM_DB_URL` | `sqlite:///backend/data/system.db` | 系统自身库。生产可换 PostgreSQL |
| `APP_SECRET_KEY` | 内置开发值 | **生产必须改**，用于加密钉钉 webhook 和数据库密码 |
| `MAX_ROWS_HARD_LIMIT` | `200` | 单条推送最大行数上限，防止刷屏 |
| `APP_DATA_DIR` | `backend/data` | 数据目录 |
| `PUBLIC_BASE_URL` | 空 | 图片 / Excel 下载用的访问地址（仅「本系统服务器」模式）。也可在「系统设置」里改（界面优先） |
| `IMAGE_RETENTION_DAYS` | `7` | 报表图片和 Excel 文件的保留天数（仅「本系统服务器」模式） |
| `APP_PORT` | `18080` | 后端端口，只用于给「图片服务地址」生成候选值 |
| `VITE_API_TARGET` | `http://127.0.0.1:18080` | 前端开发代理目标 |
| `VITE_PORT` | `5173` | 前端开发端口 |

## 五、接入 PostgreSQL（只读）

**第一步：在数据库上建只读账号**

```sql
CREATE ROLE push_reader LOGIN PASSWORD '你的密码';
GRANT CONNECT ON DATABASE your_db TO push_reader;
GRANT USAGE ON SCHEMA public TO push_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO push_reader;
-- 以后新建的表也自动授权
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO push_reader;
```

**第二步：在系统里添加数据源**

进入「数据源」→「添加数据源」，类型选 `PostgreSQL`，填地址、端口、库名、`push_reader` 账号密码，点「测试」。

系统只发 `SELECT`，且自定义 SQL 模式做了三重校验（必须以 `SELECT`/`WITH` 开头、不允许多条语句、强制包含 `{region}` 归属地占位符），不会修改任何业务数据。

## 六、钉钉配置

**第一步：建群机器人**

钉钉群 → 群设置 → 智能群助手 → 添加机器人 → 自定义 → 安全设置选「加签」→ 复制 Webhook 地址和签名密钥。

**第二步：填进系统**

「钉钉群」→「添加钉钉群」，粘贴 Webhook；如果用了加签，把密钥填到「加签密钥」。点「测试发送」验证。

**第三步：@ 人的前提**

用钉钉自定义机器人 @ 人，**手机号必须在该机器人所属企业的通讯录里能匹配到**，否则消息照常发出去，但 @ 会不生效（钉钉不会报错）。这是钉钉的限制，不是系统的问题。

## 七、权限怎么生效

### 归属地隔离（数据行级）

数据隔离在**数据层强制注入**，不依赖前端隐藏：

1. 用户输手机号 → 系统查人员信息表拿到归属地
2. 规则里配了「归属地字段」后，系统自动在 SQL 的 `WHERE` 里加上该字段的过滤条件
3. 过滤时会把该区县的**所有别名写法**一起带上（`襄都区 IN ('襄都区','襄都','桥东区','桥东')`），解决报表名称不统一的问题
4. 非管理员登录，规则列表也只返回自己归属地的规则

需求文档里记录的实测脏数据（同一份报表里 `内邱` 和 `内丘` 并存、`达活` 这种脏值、重复列名、汇总行混在明细里），都在「归属地字典」和样例解析器里做了对应处理。

### 资源可见权限（谁能用哪些数据源 / 钉钉群）

A 地用户看不到 B 地的东西，除了上面这层行级过滤，还有一层「谁能用哪些数据源、发到哪些钉钉群」：

1. 在「数据源」/「钉钉群」的编辑弹窗里，切到第二个页签「可见权限」，勾人（支持按姓名或手机号搜索）
2. **一个都不勾 = 所有人可用**；勾了之后，只有勾上的人在建规则时能选到这个数据源 / 钉钉群
3. 管理员不受限制，永远看得到全部
4. 规则编辑页里的数据源下拉、钉钉群下拉，都会按当前登录人先过滤一遍

> ⚠️ 这一层是**防误操作**级别的：系统没有登录态，是前端把自己的手机号带给后端做过滤的。
> 直接调接口、伪造手机号是绕得过去的，别把它当安全边界。要真正的身份认证，建议接公司统一登录（钉钉扫码 / LDAP）。

## 八、生产部署建议

1. **前端打包**
   ```powershell
   cd G:\codex\jijiantongzhi\frontend
   npm run build      # 产物在 dist/
   ```
   把 `dist/` 交给 Nginx 或 IIS 托管，并把 `/api` 反向代理到后端。

2. **后端常驻**：用 NSSM 注册成 Windows 服务，或 IIS 的 ARR + 反向代理。
   ```powershell
   # 示例：注册为 Windows 服务
nssm install JijianPush "python" "-m uvicorn app.main:app --host 0.0.0.0 --port 18080"
   ```

3. **必须改的配置**
   - `APP_SECRET_KEY` 改成随机长字符串
   - `SYSTEM_DB_URL` 指向 PostgreSQL 的**可写**库（系统自己的库需要写）
   - 业务数据源用**只读**账号
   - 用了图片推送：把「系统设置 → 图片服务地址」改成钉钉客户端访问得到的地址，并确认 `/static/reports/`
     能通过反向代理直接访问（它不经过 `/api`），否则钉钉群里只会显示一个裂图

## 九、已知限制

- **登录不设密码**：只需手机号，属于「防误操作」级别，不防越权。如需真正的身份认证，建议接入公司统一登录（钉钉扫码 / LDAP）。
- **调度最细到小时**：架构已按「任意 cron 表达式」设计。后续要分钟级，只需在 `scheduler.py` 里加 `IntervalTrigger(minutes=n)` 分支，前端频率选项加一项即可。
- **触发判定目前有两种：逐行阈值、同一字段累计达到标准**：环比 / 同比、连续趋势、数据沉默（该报没报）、动态阈值（阈值存在表里）、跨表关联还没做，底层结构已预留（判定作用在聚合结果上，加一种判定方式不用改数据流）。
- **冷却按规则维度**：同一规则整体冷却，暂不支持「同一个小区 N 小时内只提醒一次」这种按对象的精细冷却。
- **图片 / Excel 链接是公开的**：本机模式的 `/static/reports/xxx.png`、`xxx.xlsx` 和图床模式的公网地址都不带登录校验，靠随机文件名 + 过期清理兜底，别往里放不该外传的数据。图床模式建议把「图片过期天数」设成和保留天数一致，让图床自己删。
- **Excel 附件的传送依赖图床**：钉钉自定义机器人本身发不了文件，只能给下载链接。图床大多只收图片，xlsx 被拒时系统会自动退回本系统地址（本机地址手机端可能下载不了），所以「发送 Excel」最好配公网可访问的地址或确认所用图床放行 xlsx。
- **图床只接了蜜蜂图床的接口**（`/api/v2/upload`）。已按官方文档支持 `file` / `storage_id`（必填）+ `expired_at` / `intro` / `is_remove_exif` / `is_public` / `tags[]` / `album_id`（后四项登录态才生效）。换别家图床只需改 `image_host.py` 里的 `upload_png`。
- **图床额度有限**：匿名约每小时 3 张（按 IP）。图片内容没变时会复用上次的链接（`backend/data/image_cache.json`），仍然超限就自动退回文字表格版。
- **图片每次推送都会重新生成**：因为数据本来就不同；内容一致时才走上面的复用。历史图片按保留天数清理。
- **前端未做移动端适配**：内部系统，以桌面浏览器为主。
- **自定义 SQL 模式未在前端暴露入口**：后端已支持（`query.mode = "sql"`），给高级用户留的后门。
